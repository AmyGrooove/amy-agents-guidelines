# Route Project Changes

On explicit invocation, identify the requested result, affected artifacts, and applicable guidance from skill descriptions and necessary project evidence. This skill provides an ownership assessment; native Codex discovery selects specialized skills during ordinary work.

Follow [workflow and authority](../../references/shared/workflow-and-authority.md) once. Keep component-, model-, API-, endpoint-, and entity-owned internals with their owner. Mechanical consumer adaptations stay with that owner; independent behavior, structure, or contract changes may need another specialized skill. Read only applicable skills and references, not candidates merely to confirm exclusions.

If no specialized Amy skill applies, use the shared workflow and project instructions and conventions directly. Do not force an unrelated skill. Unmatched tasks remain supported without invoking this skill.

An ownership assessment does not authorize implementation, expand scope, or override restrictions on tests, Storybook, documentation, commits, or external actions. Perform file changes only when the request also authorizes them. Report the assessment when requested; no activation announcement or routine route report is required.
